# SL-CRM-REQUIREMENT-UNIFY-01 Completion Report

## Objective
Unify the representation of requirement data between the global `Requirements/List.jsx` and the customer detail `Customers/View.jsx` screens, ensuring consistency with the Buyer App architecture. Additionally, ensure that the raw JSON placed in `requirements.notes` by the Buyer App is parsed and displayed beautifully rather than shown raw.

## Architecture
- **Single Source of Truth**: The CRM `requirements` and `requirement_items` tables act as the central source of truth for both the Buyer App orders and CRM requirements.
- **View Enhancements**: Added `demand_ref` and `notes` to `v_board_requirements` in `105_pending_requirements_view.sql` so global views can access Buyer App order IDs and delivery notes.
- **Unified Rendering logic**: Both the flat layout in `Requirements/List.jsx` and the card layout in `Customers/View.jsx` now render the `demand_ref` prominently and gracefully combine multiple products dynamically instead of relying on a fallback `product_type`.

## What Was Changed
1. **`105_pending_requirements_view.sql`**: Added `demand_ref` and `notes` and applied the migration to the Supabase instance.
2. **`Requirements/List.jsx`**:
   - Flat view: Renders `demand_ref` instead of raw `product_type` alone. Correctly formats aggregated item information.
   - Table view: Added a sub-label for `demand_ref` below the main product string.
3. **`Customers/View.jsx`**:
   - Replaced generic logic that displayed `"Unknown Product"` with robust iteration over `req.requirement_items`.
   - Now renders the `demand_ref` (e.g. `D-108`) if it exists, matching the format generated by the Buyer App.
4. **`Requirements/View.jsx`**:
   - Implemented a parser for `req.notes` in the "Initial Notes" section.
   - Instead of rendering raw JSON (`{ "address": "...", "extras": { ... } }`), the CRM now displays "Delivery Notes / Address" with a cleanly formatted `address` and `client_reference_id` when the note is JSON. Falls back smoothly to plain text if a user added a standard note in the CRM.

## Verification
- Both the Requirements Global Board and Customer Specific Requirements tabs show matching, unified views of the underlying single order data.
- The raw JSON note is gracefully parsed and hidden from standard business users. No new tables were introduced, keeping architecture intact.
